# Verdicto Explainer: Architecture & Run Guide

Welcome to **Verdicto** — an AI-powered, multi-agent legal research platform designed to search, analyze, and debate Indian Supreme Court judgments. This document provides a complete technical walkthrough of the project and detailed instructions on how to set up, ingest data, and run it locally.

---

## 1. Project Architecture

Verdicto utilizes a modern web stack coupled with a custom multi-agent orchestration layer.

```
       ┌────────────────────────┐
       │   Frontend (React)     │
       │   Vite (Port 5173)     │
       └───────────┬────────────┘
                   │ HTTP REST (apiClient.js)
                   ▼
       ┌────────────────────────┐
       │   Backend (FastAPI)    │
       │   Uvicorn (Port 8000)  │
       └─────┬────────────┬─────┘
             │            │
             │            ├──────────────────────────────┐
             ▼ (asyncpg)  ▼ (faiss CPU)                  ▼ (Ollama API)
       ┌───────────┐ ┌───────────────┐            ┌───────────────┐
       │ Postgres  │ │  FAISS Index  │            │ Local Ollama  │
       │  (5433)   │ │  (local flat) │            │ (Port 11434)  │
       └───────────┘ └───────────────┘            └───────────────┘
         Metadata     384-dim Vectors             LLM (DeepSeek)
```

### Key Components

1. **Frontend (`Frontend/webapp`)**:
   - Built with **React 19**, **Vite**, **lucide-react**, and **react-router-dom**.
   - Includes full-featured visualization pages (workflow visualizer, interactive citation networks, dashboard, similar cases, case viewer).
   - Utilizes a centralized [apiClient.js](file:///d:/Verdicto/Frontend/webapp/src/lib/apiClient.js) layer to communicate with the FastAPI backend.

2. **Backend Services (`Backend/app`)**:
   - Built with **FastAPI** utilizing async handlers and SQLAlchemy + asyncpg for efficient database access.
   - Vector Search is handled via a **local FAISS IndexFlatIP** storing 384-dimensional dense vectors generated by a local `all-MiniLM-L6-v2` SentenceTransformer model.
   - Relational Metadata is stored in **PostgreSQL 15**, utilizing TSVector indexes for keyword-based search.
   - Long-running multi-agent pipelines are processed asynchronously using FastAPI's built-in `BackgroundTasks` framework (which writes updates back to the `query_records` table in PostgreSQL so the frontend can poll status).

## 2. The Multi-Agent Orchestration Flow

When a user submits a search query, the backend spins up the **Scheduler Agent** which orchestrates a sequence of specialized AI agents:

```
[User Query]
     │
     ▼
┌──────────────┐
│Query Planner │ ──► Reformulates query, extracts issues and factual concepts.
└──────┬───────┘
       ▼
┌──────────────┐
│  Retriever   │ ──► Hybrid Search: Local SentenceTransformer embedding + FAISS search
└──────┬───────┘     merged with Postgres BM25 keyword search via Reciprocal Rank Fusion (RRF).
       ▼
┌──────────────┐
│  Precedent   │ ──► Applies weight calculations: Bench size (35%), Citation count (20%),
│  Weighting   │     Recency (15%), and factual context alignment (20%).
└──────┬───────┘
       ▼
┌──────────────┐
│ Debate Agent │ ──► Multi-round advocate debate using Ollama (DeepSeek-R1) to evaluate
└──────┬───────┘     arguments for/against precedent relevance and filter out weak citations.
       ▼
┌──────────────┐
│  Evaluator   │ ──► Calculates retrieval statistics (P@5, nDCG@10, MRR, Issue Coverage).
└──────┬───────┘     If confidence score < 0.55, schedules next iteration (max 3).
       ▼
[Final Results] ──► Combines consensus rationale, ratio decidendi, and legal details.
```

1. **Query Planner Agent**: Decomposes the user's search query, identifies the core legal domain, and generates search reformulations.
2. **Retriever Agent**: Performs semantic FAISS search and keyword BM25 search, combining the lists via RRF.
3. **Precedent Weighting Agent**: Inspects bench size, citation count, recency, and factual alignment to re-rank results based on "legal authority."
4. **Debate Agent**: Simulates an advocate-moderator system (Claims, Counterclaims, Synthesis) utilizing DeepSeek-R1 to debate case relevance.
5. **Evaluator Agent**: Evaluates issues addressed vs query issues and assigns retrieval confidence metrics.
6. **Scheduler Agent**: Manages the loop. If confidence is low, it triggers refinement iterations (capped at 3).

## 3. Step-by-Step Run Guide

Follow these steps to configure your environment, ingest judgment data, and run the applications.

### Prerequisites
* **Python 3.11+**
* **Node.js 18+** & npm
* **Docker & Docker Compose** (for Postgres and Redis)
* **Ollama** installed on the host machine.
  * Pull the required model: `ollama pull deepseek-r1:8b`
  * Pull the embedding model (only if using Ollama embeddings, default uses SentenceTransformers): `ollama pull nomic-embed-text:latest`

---

### Step 1: Start Infrastructure (Database & Redis)

Launch the database and Redis cache containers using docker-compose:
```bash
docker-compose up db redis -d
```
*Note:* The database container is mapped to **port 5433** on the host. Inside the Docker network, it communicates on port **5432**.

---

### Step 2: Environment Configuration

Verify the `.env` file exists in the project root. If not, copy it from `.env.example`:
```bash
cp .env.example .env
```
Inside `.env`, verify the following configurations:
```ini
# If running FastAPI directly on host (recommended for dev):
DATABASE_URL=postgresql+asyncpg://verdicto:verdicto_secret@localhost:5433/verdicto
REDIS_URL=redis://localhost:6379/0

# If running inside Docker Compose container:
# DATABASE_URL=postgresql+asyncpg://verdicto:verdicto_secret@db:5432/verdicto
# REDIS_URL=redis://redis:6379/0

FAISS_INDEX_PATH=./data/index/cases.index
FAISS_MAPPING_PATH=./data/index/cases_mapping.json
```

---

### Step 3: Run Database Migrations

Set up the python virtual environment, install dependencies, and run migrations:
```bash
# From the project root
cd Backend

# Create & activate virtual environment
python -m venv venv
# On Windows (PowerShell):
.\venv\Scripts\Activate.ps1
# On Linux/macOS:
source venv/bin/activate

# Install dependencies
pip install -r requirements.txt

# Run migrations to create schema
alembic upgrade head
```

---

### Step 4: Populate Data & Build Vectors (Ingestion Pipeline)

Since the `data/` directory is initially empty, you must run the ingestion pipeline.

> [!IMPORTANT]
> The database populate script (`populate_db.py`) must be executed after segmenting to ensure the Postgres `cases` table is filled. Running only `ingest.ps1` will miss the DB loading step.

Run the pipeline steps sequentially from the **`Backend`** folder (with venv active):

1. **Download source data** (Tar archives of PDFs & Parquet metadata for a year, e.g. 2024):
   ```bash
   python -m scripts.ingest.download_dataset --year-from 2024 --year-to 2024 --output-dir ../data/raw
   ```
2. **Extract PDF contents**:
   ```bash
   python -m scripts.ingest.extract_text --input-dir ../data/raw/pdfs --output-dir ../data/processed
   ```
3. **Segment texts** (split into facts/issues/reasoning/outcome sections):
   ```bash
   python -m scripts.ingest.segment_text --input-dir ../data/processed --output-dir ../data/processed/segmented
   ```
4. **Load data into PostgreSQL**:
   ```bash
   python -m scripts.ingest.populate_db --segmented-dir ../data/processed/segmented --database-url postgresql+asyncpg://verdicto:verdicto_secret@localhost:5433/verdicto
   ```
5. **Build embeddings** (generates `.npy` embeddings using local SentenceTransformer):
   ```bash
   python -m scripts.ingest.build_embeddings --input-dir ../data/processed/segmented --output-dir ../data/embeddings
   ```
6. **Build local FAISS vector index**:
   ```bash
   python -m scripts.ingest.build_faiss_index --embeddings-dir ../data/embeddings --output-dir ../data/index
   ```

---

### Step 5: Start the Backend API

Start the FastAPI backend server using Uvicorn:
```bash
# Inside Backend directory with venv active
uvicorn app.main:app --reload --port 8000
```
* Interactive documentation is available at [http://localhost:8000/docs](http://localhost:8000/docs).
* Health checks can be verified at [http://localhost:8000/api/v1/health](http://localhost:8000/api/v1/health).

---

### Step 6: Start the Frontend Application

Open a new terminal window to build and run the React frontend:
```bash
# Navigate to webapp from project root
cd Frontend/webapp

# Install dependencies
npm install

# Start development server
npm run dev
```
* The application runs locally at [http://localhost:5173](http://localhost:5173).

## 4. Troubleshooting & Notes

* **PostgreSQL Port Mismatch**: If running migrations or scripts on the host, always target port **5433** (`localhost:5433`). The default port in some configurations is `5432`, which will cause connection errors if Postgres is running inside the Docker container.
* **Ollama Connection**: The backend expects Ollama to be running on the default local port `11434`. Ensure `ollama serve` is active and the model `deepseek-r1:8b` is pulled. If Ollama is running inside another container, you can update `ollama_url` in `Backend/app/core/config.py` (e.g. to `http://host.docker.internal:11434`).
* **Background Processing**: Query pipelines run in the background via FastAPI background tasks. Ensure your PostgreSQL connection remains active during query processing, as agent trace logs are written directly to the database in real time.
* **Sentence Transformers Model Download**: When starting `build_embeddings.py` or the server, `sentence-transformers` will automatically download `all-MiniLM-L6-v2` from Hugging Face if it is not cached locally. Ensure you have an active internet connection on the first run.
